# Directory watching and extended attributes

The original ARM64 library's syscall dispatcher was followed to its inotify and eight pathname-xattr helpers. Each uses the configured forward path mapper and then the genuine operation, retaining its other arguments. Static evidence comes from the supplied GBox APK SHA256 `6fcbaafbcb033b9e0cc03a5d6acaa54ca6b6cb06d16ce3c2d0657d7addfba257`, library SHA256 `daf9e3844d5d6c750dcd360745d3595621719c0809c8b93fb8b665799c81ac3a`. REA's Windows native provider does not support this ELF; these particular function observations use the existing standalone Ghidra 12.1.4 project and byte-checked ARM64 disassembly, separately from REA Java evidence. Original code and binaries remain outside this repository.

Mylite adds `inotify_add_watch`, set/get/list/remove xattr and their `l*` variants to the existing shared pathname dispatch table. That table also generates the actual seccomp filter. Only the pathname is rewritten using the existing bounded, fault-safe copy and rules; watch FD/mask, attribute name/value/size/flags, symlink-follow distinction, actual return and kernel errno stay authoritative. Descriptor-only xattr operations already address the opened file and need no pathname adaptation. This does not grant new filesystem or SELinux permissions.

The native runtime probe requires a real watch on the virtual directory, the same watch identity when addressed physically, an actual create event and matching physical file. It checks invalid pathname and non-directory errors. Attribute probes compare virtual operations with the same physical filesystem, include binary values and create/size errors when supported, and report actual regular/symlink attribute support separately. Unsupported or denied attributes must return the real physical error; that comparison is not positive evidence that the filesystem supports attributes.

Linux x86_64 and AArch64 probes passed three rounds. AArch64's real regular-file attributes were supported; symlink attributes were rejected by its actual filesystem policy. Core run [40210729960](https://github.com/xmy953538104/Mybox/actions/runs/40210729960), revision `16589b4`, also passed the actual Android 14 x86_64 guest FileObserver/xattr test in all three 81-test rounds: a genuine CREATE event and physical file are required, and attributes must match that same physical filesystem's supported/unsupported result. This does not establish ARM64 Android, OEM behavior or original-engine performance parity.

The current relative-path policy still preserves real kernel cwd/dirfd behavior. Original conditional proc directory filtering and stat/statfs metadata policies are separate remaining work: trap registration alone is not their specification. Some original wrappers also appear to zero-extend negative 32-bit results; Mylite retains its correct signed raw syscall errors instead of reproducing that unverified defect.

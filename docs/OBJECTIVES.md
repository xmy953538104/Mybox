# Mybox / Mylite 目标与验收约定

2026-10-24 用户恢复工作并确认：Mybox 是应用产品，Mylite 是我们独立实现的容器核心；VLite 仅指原 GBox 样本中的参考引擎。

目标是在普通 Android 上重建 GBox 核心可观察行为，同时验证兼容性、性能和稳定性。2026-10-25 用户进一步明确范围：除 GBox 会员、GBox 自有账号体系、HMS 及使用限制之外，其余功能均属核心；Google 账号登录不在排除范围内。不能用旧 BlackBox 原型代替 Mylite，也不能把编译或少量自有 fixture 通过当作完整复刻。

- 以用户提供的 GBox APK 为参考，深入 REA 调用链、配置和原生边界，保存工件 hash、Evidence ID、明确未知项。原生分析工具与 REA 证据分别标注。
- 2026-10-27 用户更新强制顺序：任何功能走不通、功能验证/运行失败或出现新应用异常，第一项诊断动作就是用 REA 对照原版 GBox；取消“两轮失败后升级”的门槛。必须一起查看完整调用链、关联配置/开关、身份权限、初始化顺序、持久化和恢复状态，在据此选择修复或重跑前补齐缺失证据；不得只看孤立方法或先猜修再补分析。仍须收齐整批结果并关联所有失败后才修改运行逻辑。
- 仅发布自主可构建的 Mylite 源码与来源明确的开源依赖，不装入原 VLite 私有二进制；无需安装 Xposed 框架。
- 先完成 Google 服务与应用关键链：microG 初始化、真实 Google 登录、Play 下载/安装、地图和推送。每条链必须有实际结果，不能伪造账号、token、安装成功或静默吞错。
- 将失败追到根因，并以对应负向/恢复测试锁住；分开报告静态证据、JVM、Linux、模拟器与真机结果。
- 性能必须记录环境与基线，测冷/热启动、Binder往返、原生I/O、内存和后台唤醒；稳定性需重复运行、更新/重启恢复和异常路径。缺少同环境对照时不得声称与原版性能等同。
- 云端稳定后及时提醒用户提供 Y700 真机环境。当前只用电脑与 CI，未经进一步安排不占用用户平板；ARM64/OEM后台策略/16KB页等不能由x86_64结果替代。
- 本轮用户再次要求先在云端和模拟器验证，不访问 Y700。先完成逐功能的原版入口、调用链、状态/恢复、异常边界与差距清单，再依证据实现和对照；不得把清单或静态方法注册当成功能已经完成。

2026-10-26 后续授权覆盖上述暂不访问设备的阶段性安排：用户明确表示当前可配合登录，开放Y700；一次实际登录UI完成后Play崩溃，继续依据整批实际栈及原版REA处理。保留已登录数据，先修复、云端验证，再安排实际商店返回及下载安装；无需用户重复提供凭据。

当前阶段优先次序：完成待验收的总装闭环 → 按原行为补齐 Provider 依赖初始化 → 核心服务覆盖矩阵与 Google 链路 → 后台调度与进程恢复 → 性能/稳定性对照 → Y700 真机验收。顺序随实际证据调整，原目标不因阶段完成而缩减。

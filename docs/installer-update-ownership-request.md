# Optional update ownership request

Y700 with `1437e7d` reached the actual Play installation request after the package-query fix. Installation still failed before creating a virtual session. Original GBox REA was the first diagnostic action; retained commit/install/configuration evidence was followed by exact platform-to-virtual SessionParams conversion and server createSession/owned-session registration.

The actual exception is `InstallerWire.params` throwing UnsupportedOperationException at DEX code index335. A bounded, class-filtered debugger observation read only the owned SessionParams' whitelisted numeric fields: full mode1, flags0x2404000, internal installLocation1, user installReason4, packageSource0, default requireUserAction0. Both observed requests were retained. No account, credential, generic object field or raw exception message was read.

The unsupported bit0x2000000 is `INSTALL_REQUEST_UPDATE_OWNERSHIP`. Android14's [PackageInstallerService](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-14.0.0_r1/services/core/java/com/android/server/pm/PackageInstallerService.java#L863) removes this optional request when ENFORCE_UPDATE_OWNERSHIP is unavailable. The Mybox host does not request that permission. Original GBox carries platform flags into its virtual session, then dispatches the actual internal installation through its own configuration; that is not evidence that every platform installer flag is enforced.

The candidate recognizes the optional request and declines update ownership. Session and SessionInfo report false; the committed InstallSourceInfo has no update owner. Installer attribution still records the actual authorized installer, which is distinct from update ownership. No physical or virtual ownership privilege, runtime permission, bypass, installation result or package state is fabricated. Other unsupported flags and permission mutations remain rejected.

The existing ordinary-guest installer fixture requests update ownership during its actual signed v1-to-v2 PFD/resume/fsync/commit/status-broadcast/listener path, checks both session views, then verifies no owner appears after real publication. The host confirms its permission is denied and existing app data/appId remain. A runtime-permission-grant flag stays a negative case. Full cloud batches and retained-account Play download/install/open remain required.

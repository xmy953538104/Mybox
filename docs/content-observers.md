# Container content observers

Mylite routes observer registration, removal and ordinary notifications for committed virtual authorities to its own server. Physical content observers keep their OS path. The server authenticates the real UID/PID and current sealed process generation, validates the observer Binder interface and user zero, and selects Provider metadata independently. Google service authorities cannot silently fall back to physical GSF/GMS.

The current cross-package scope is unrestricted exported Providers only. Private, read/write protected and path protected peers are rejected. Same-package providers retain their existing access. URI grants, protected peer permissions, sync adapters, mixed physical/virtual batches and sync-to-network notifications remain explicit unsupported operations. This is not full ContentService or Provider permission parity.

Subscriptions keep original authorities and path segments. Notifications preserve URIs, self origin and wire flags, apply exact/ancestor/descendant matching and `NOTIFY_SKIP_NOTIFY_FOR_DESCENDANTS`, and invoke the actual framework observer transport. Limits are 64 registrations per sealed process, 256 total and 64 URIs per notification. Binder/process death removes subscriptions; no stale virtual process is reauthenticated by package text.

Matching semantics were checked against [AOSP14 ContentService](https://android.googlesource.com/platform/frameworks/base/+/android-14.0.0_r1/services/core/java/com/android/server/content/ContentService.java).

The synthetic guest uses a real remote Provider process and normal ContentResolver calls. It checks path isolation, ancestors, self exclusion/delivery, skip flags, removal, rejected sync, registration quota and five complete remote process generations. A separate real server-death test verifies that the host reconnects and can launch a guest again. Metadata negatives preserve private/read/write/path restrictions; an unregistered host cannot acquire the guest endpoint.

The fixture/physical host targets SDK28. Android's legacy three-argument ContentObserver callback reports userId instead of modern notification flags. The test asserts that real legacy behavior; it does not claim modern-target callback compatibility. API26–29 flag callbacks, OEM policy, 16KiB pages and performance parity remain unverified.

Local API31 preserved failures: initial two-test run failed a modern-flags assumption and acquired the endpoint from an unauthorized host; corrected observations passed 2 tests in 1.747 seconds, and added metadata checks passed 3 in 1.841 seconds. The engine now reacquires once only after actual DeadObjectException during bootstrap, within its existing budget; other failures still propagate. The four-test round then passed in 4.946 seconds.

# Storage attribution

Actual Play53.6.15 failed disk-space collection through Environment.isExternalStorageEmulated→StorageManager.getVolumeList with `callingPackage does not match UID` in full40266218650. Original new-GBox REA g4.b.a/registration/compat branch (ev_06f3086350ae8ce200e98ec1ad97e41f55676940b9163ad0c5622805776cc91e, ev_c71f6f420aeefab536a9d25d5ac4fc10d4565a473c766f62a9f09325c66c958d, ev_ed709f73c12b43b32485499a9b1541379c177ad1923b9fef290954ca9a540b3b) maps package and the first integer. Fixed official AOSP26–35 interfaces confirm that integer means UID through32 and userId from33; the32 preview branch also uses userId.

The candidate installs a local IStorageManager facade in ServiceManager's mount cache and the existing host StorageManager instance. Exact local caller, own bound guest/host package, own guest/physical UID or supported virtual/physical user are required. It maps getVolumeList, own-UID cache-size/quota queries, and package-attributed allocation queries while preserving UUID, bytes, flags, actual OS volume/results and original exceptions. API26 allocation has no package argument; API27+ does. No volume, capacity, quota, successful allocation or permission is synthesized. Cache results are the real shared host UID's OS accounting, not per-guest kernel quotas.

Original x0.c's four method registrations decode to mkdirs/getVolumeList/getCacheQuotaBytes/getCacheSizeBytes. Retained original getCacheQuotaBytes returns zero; this independent implementation keeps the real OS quota instead. Original fallback reconstruction after getVolumeList failure and mkdirs fallback are not copied. Other methods retain their actual backend behavior, permissions and errors; external mkdirs Binder attribution/path compatibility remains unimplemented and must not be hidden if encountered. Raw transactions retain physical OS checks and are not adapted. This is not a kernel security boundary against arbitrary same-UID native code.

JVM checks cover26–35 signatures/preview branches, unrelated-identity rejection, unchanged inputs/bytes/flags and exact backend result/error preservation. A real fixture records static Environment calls, instance volume queries, actual data/external StatFs and real allocation/cache queries; its data capacity must equal the actual host filesystem. Both fixture and actual Play startup must be revalidated in cloud. This candidate has not yet passed that batch; it is not authentication, download or Y700 acceptance.

Official interface example: https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/os/storage/IStorageManager.aidl . The full26–35 source hashes and private reconstruction specification are retained outside Git.

# Mybox / Mylite

- Mybox is the app; Mylite is the independent core in `mylite-engine`. VLite names refer to original-artifact evidence, not our product.
- Read `docs/OBJECTIVES.md` and `docs/STATUS.md` before changing runtime behavior. The user requires GBox core compatibility, performance and stability, excluding VIP and HMS; a settings screen or fixture pass is not full acceptance.
- Use REA evidence to guide reconstruction. Keep original APKs, private binaries and decompiled original code out of this repository. Do not reintroduce inactive Bcore as the implementation.
- Preserve real signature/caller checks and actual Android completion/error semantics. Do not fake Google accounts/tokens, installation results, task completion or foreground status.
- Before restricting a package argument to self, verify its meaning against the original chain and actual Android callers. A used dependency, code-loading owner and opPackage attribution are different contracts; include the real WebView/class-loader consumer when changing these shared paths.
- Keep guest/API failures and important installer/job lifecycle events observable through EngineDiagnostics. Debug defaults OFF; bound persistent storage, retain error history, count dropped events and export only fixed-schema fields, never account names, credentials, tokens, arbitrary Bundles/Intents, URLs/bodies or raw databases. Missing logs are not success; verify actual exported events alongside real operations.
- Keep app identity, existing data and account-key compatibility during renames. Unknown unsupported behavior must remain visible until implemented and tested.
- Current verification uses PC/static tools and disposable CI emulators. Coordinate with the user before Y700/physical-device work; notify them when cloud results are stable enough to need real hardware.
- For timed device access, record and enforce a deadline. Stop starting new app journeys with less than five minutes left, and begin journal export, debug OFF, HOME and observer shutdown at least three minutes before expiry. After the first matching REA lookup, preserve the live failure and finish deeper static analysis after device cleanup. If expiry prevents cleanup, stop all device access and report the unfinished steps; obtain a fresh window before any further device command.
- Before tapping an Android control near the keyboard, verify the composed screen as well as fresh accessibility bounds; floating IME windows can cover controls still present in the UI dump. Dismiss the keyboard and verify the expected result/file instead of retrying covered coordinates.
- Build/check: `:mylite-engine:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`; audit both host and test APK with `scripts/audit-reconstructed-apk.py`.
- Runtime evidence must distinguish Linux, Android emulator and ARM64/OEM hardware. Keep every stability round and raw benchmark environment/results; never retry away a failure or claim unmeasured parity.
- Bound one-shot cloud ADB commands and retain a fixed-schema phase record on timeout. Keep intentional live streams separately managed; unavailable capture/transport makes that cohort incomplete, and a missing or partial crash snapshot is not an empty crash result. Preserve the aborted batch before changing code or arranging another run.
- For each validation batch, collect the complete round before changing runtime code. Group related failures, crashes, state contamination and subsequent failures; check original REA call chains and applicable Android behavior before choosing fixes. Record observations, inferences and unknowns separately, then fix the related paths together and rerun their regressions plus the complete Google business journey. Do not stop at the first runtime failure to patch it or treat a fixture pass as business acceptance.
- At the first blocked feature, failed functional validation/runtime attempt or new application exception, make REA investigation of original GBox the first diagnostic action. Do not wait for a second round or begin a speculative fix/retry cycle. Inspect the complete relevant call chain together with its configuration, feature flags, identity/permission setup, initialization order and persisted/recovery state; reuse matching retained evidence and obtain missing original evidence before choosing changes. Reconcile related failures and distinguish observations, inferences and unknowns. Inspecting one isolated method is insufficient. Keep collecting the complete validation batch before changing runtime code; first-failure REA does not permit patching only the first observed error.
- Check C: and E: free space before and after each build/REA/CI artifact batch. If C: falls below 25 GiB, inspect this project's generated caches before starting another local build; do not let repeated bundled-microG transforms accumulate unnoticed.
- Keep local Gradle user home and REA/Java temporary work on E: with process-scoped settings (`E:\APK-GBOX\analysis\gradle-user-home` and `E:\APK-GBOX\analysis\temp`). Do not change global environment variables or move other projects' caches. Preserve dependency downloads, wrappers, SDK/JDK, signing/ADB keys, source trees, reference APKs, active emulators, evidence, and current workflow inputs.
- Cleanup requires a saved inventory and an exact allowlist of proven project-owned, reproducible outputs or verified redundant copies. Resolve every absolute target and ancestor; reject reparse points, unexpected children and active producers. For Gradle transforms, identify project ownership by the exact `transformed/out/assets/mybox/microg-nohms.apk` marker and retain the newest two; never clear the entire shared Gradle cache.
- On Windows delete only with native PowerShell `Remove-Item -LiteralPath $target -Recurse -ErrorAction Stop`, without `-Force`, attribute changes, shell switching or string-built commands. Protected/locked files remain with a recorded reason. Save deletion outcomes and actual before/after free space, and check that retained inputs still exist.

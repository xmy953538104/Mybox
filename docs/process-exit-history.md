# Actual process exit history

The exact Play 53.6.15 APK captured in full run [40210730952](https://github.com/xmy953538104/Mybox/actions/runs/40210730952) calls `getHistoricalProcessExitReasons("com.android.vending", 0, 100)` from its Application constructor helper. The unadapted call reached Android with a virtual package and physical host UID and failed the real DUMP permission check. REA of that APK, SHA256 `5d062e4acbe631a0c3683cd0654637ec5724cd18890e1a272be834622d2660b3`, recovered `defpackage.rrz.<init>(ActivityManager)` (Evidence `ev_0fef248a7ac63d0a1fa9bd3aef3f567164d52ef8a70e372556c875b2b54551f5`). This is a distinct blocker from the older Play 35 initialization wait.

REA of the supplied original GBox recovered its corresponding forwarding hook, `com.vlite.sdk.client.hook.service.am.d.t.g` (`ev_bb14d384d76f66ac40ca9b6d705360df7626ecc03446f0558460549009eb9445`), and result handling `am.d.j` (`ev_8be3250a5e9f58d5ab800a4f78dd33aebc72774adb03353666de1feb72da9c2c`). Those methods adapt package/user, invoke the OS, rewrite a package field and catch errors. The recovered methods do not establish guest ownership filtering. Mylite implements its own boundary rather than exposing all host history or swallowing that error.

On API30+, the server queries the genuine host OS history without requesting DUMP. A private AtomicFile journal records the validated process reservation before Application binding, after the actual death listener is installed. It associates installation identity, logical/physical process, PID and clock anchors; a successful write is synced and read back. Real Binder death retires the reservation. Journal corruption or persistence failure remains an error; a failed seal retires the actual prepared VM through existing process cleanup. Unreferenced installation mappings are reclaimed, so bounded history does not create a lifetime app-install limit.

Only rows attributable to the authenticated guest installation are returned. Filtering precedes sorting/limits; real reason, status, timestamp, memory and process-state summary remain authoritative. Logical process/package names are adapted while UID follows the existing physical ApplicationInfo view. Package updates retain the trusted installation identity. Future production uninstall must explicitly retire the installation epoch; production uninstall is not implemented by this change.

Unknown pre-journal rows are not assigned by slot name. PID/slot reuse, an existing PID baseline or a detected boot/clock discontinuity prevents new ambiguous attribution; already confirmed record keys remain usable. This deliberately does not claim complete correlation after arbitrary unobserved clock changes or for unregistered isolated child processes. The journal retains at most 256 reservations and confirmed records, rather than inventing history the OS no longer supplies.

Returned trace interfaces are scoped Binder capabilities, never the raw OS retriever. They verify the current caller/installation and exact selected record, fix physical forwarding arguments, recheck before/after opening and close failed file descriptors. Actual OS null/exception outcomes remain visible. Android tests require a real killed guest's summary/reason/status, peer/host exclusion, filtering before max1, server replacement, foreign trace arguments and actual AtomicFile failure cleanup. They do not create a real ANR or native tombstone: positive trace bytes/FDs, actual PID reuse, other Android releases and OEM behavior remain separate acceptance work. Final local compilation took 34 seconds; 85 JVM checks, lint and APK audits passed. New Android execution and the resumed Play journey are pending.

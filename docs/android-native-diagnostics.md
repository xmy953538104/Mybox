# Standalone Android/bionic native diagnostics

The manual-only `android-native-diagnostics.yml` workflow cross-compiles the native assertions against NDK **27.2.12479018 / API26** for ARM64 and x86_64, then runs the x86_64 executable three times on a disposable Android 14 emulator. It installs the same-source debug host APK and uses `run-as io.github.xmy953538104.mybox`, checking the installed UID before execution. It never selects a physical device, grants root, changes SELinux, or runs the ordinary instrumentation/full-bundle scripts.

This profile exercises bionic's real pthread and signal implementations with the host's real Linux UID. It is a **standalone executable**, started before creating threads, rather than a `fork()` from ART. `run-as` selects a `:fromRunAs` SELinux context in [Android's implementation](https://android.googlesource.com/platform/system/core/+/android-14.0.0_r1/run-as/run-as.cpp); it is not evidence of the zygote/ART process domain or identical inherited seccomp policy. The executable itself records UID/GID, PID/PGID/SID, page size, `/proc/self/status` and its actual SELinux context. Kernel, fingerprint, security patch, NDK/compiler, Git SHA, ELF headers/build ID/dependencies and local/on-device binary SHA256 are retained. ARM64 is cross-compiled only; ARM64 Android, OEM kernels and 16 KiB pages remain unmeasured.

Default Android product builds remain unchanged. `MYLITE_BUILD_ANDROID_NATIVE_TESTS=ON` creates a separate `MYLITE_NATIVE_TESTING` core and the `mybox-mylite-native-test` executable. The standalone configuration requires `ANDROID_STL=c++_static`; it still uses the device's dynamic bionic, but does not require a separately staged `libc++_shared.so`. Neither the test-only hooks nor the executable are added to the product shared library. The six physical temporary directories use a bounded test helper and `TMPDIR` inside the unique private run directory; Linux retains `/tmp` as its default. Logical guest paths are unchanged.

Every round retains the original native assertions: both 389-case wait error matrices; all five actual wait/EINTR paths; eleven exact install-guard cases; preinstalled/nested signal behavior on the main and TSYNC worker threads; eight occupied stack slots plus real fallback and allocation failure; syscall path/error/readlink behavior. The raw `/proc` PC/syscall/SP observation is unchanged. A denied `/proc` read, blocked syscall, unavailable `epoll_pwait2`, signal delivery failure or SELinux denial is a failed/unavailable profile, never an accepted skip. A later passing round cannot replace any failed round.

The runner creates one new session using [Android toybox `setsid -w`](https://android.googlesource.com/platform/external/toybox/+/android-14.0.0_r1/toys/other/setsid.c). Its leader records a unique cookie, PID, start time and UID before forking the watchdog or tests. All test descendants inherit that dedicated group; these test sources contain no `setsid`/`setpgid`. An unfiltered device-side watchdog enforces 60 seconds. Test completion, watchdog expiry and the leader's interruption trap each kill **group 0 from a living group member**, so they cannot target a reused numeric group. This also removes children left behind by a failed assertion. The result file is written before normal cleanup; intentional supervisor termination is not used as the native result.

The host has a separate 90-second deadline. It uses ADB shell v2 with `-T` (no PTY), preserving binary bytes, separate errors and the remote exit status. Its cleanup request verifies the original leader's PID/start time, session/group, UID and cookie before signaling that exact leader; the leader then cleans its own group. Changed identity is refused. Cleanup must confirm that the dedicated group disappeared; permission denial, lost transport or an unreaped group remains a failure/unknown and never triggers name/UID-wide killing. The disposable emulator is subsequently destroyed by the workflow. All three result/log/identity/cleanup sets and the overall JSON result are uploaded even after failure. No benchmark or performance claim is included.

Local verification covers strict NDK compilation/linking, ELF dependency checks and runner parser/safety self-tests. Actual Android results must be linked after manually dispatching this workflow; compilation alone does not establish that the run-as execution policy or `/proc` observation is available on the emulator.

At `ff57ae8`, [manual CI40078462451](https://github.com/xmy953538104/Mybox/actions/runs/40078462451) passed all three rounds (4.162/4.111/3.180 seconds including transport/cleanup). The actual Android14 kernel was 6.1.23, page size 4096, UID/GID 10192, SELinux Enforcing with `runas_app`. Before installing Mylite's filter the process had `Seccomp: 0`, `NoNewPrivs: 0`, and inherited shell supplementary groups (including GID3009); those differ from a zygote-created guest. All assertions and dedicated-session cleanup passed without a skip. The expected supervisor exit137 is separate from each native test's recorded exit0. This establishes this bionic/standalone profile only, with no ART, ARM64, OEM or 16KiB runtime claim. The test binary SHA256 was `e9c5be6933fce908bfe328541d8f93606a259b4f8115ecf77f59587b5308eaf6`.

# OS JobScheduler reconstruction

Candidate shared OS-binding integration (not yet built or Android-accepted): internal JobService binding now consumes ComponentRouter's revocable actual-OS binding handle. Its admitted boolean is never a Job start acknowledgement. The existing single physical dispatch worker waits for a real nonnull IJobService connection, verifies the fixed PREPARED owner against callback/current reservation, then installs the owner guard and forwards actual start. The original proxy's eight-second absolute deadline is carried into this wait; guard death wakes it and close revokes the same handle even before connection or after a late admission return. User callbacks/OS calls are outside the sessions/state monitors. Genuine callbacks retain their actual OS callback/virtual ID checks, including legitimate late completion.

After actual start has been sent, real asynchronous disconnection/binding death/failure chooses one terminal outcome against normal close. A failure winner uses an authenticated guard FAIL command to expose real proxy death to Android; a normal close winner releases the guard and ignores old failure callbacks. The guard independently refuses to retire after RELEASE. Failure categories are fixed constants. This still affects jobs sharing that proxy; independent per-job failure isolation is not claimed. Real null JobService binding remains an explicit failure rather than a fabricated ACK: AOSP's direct null-binding non-reschedule policy is not yet reproduced through the physical JobService bridge. New source-level Android tests cover close-vs-failure ordering and actual proxy death while a separate guest's real onBind is gated, requiring the original binding's real onUnbind with no Job start after late connection. Existing real stop/finish/other-job progression tests remain required.

Review tightened two candidate boundaries: the same original deadline is checked again after WATCH and immediately before actual start invocation, so connection/descriptor/watch work cannot create a fresh budget. Both executor/server death and FAIL now atomically claim the guard's closed state against RELEASE; an already released guard cannot retire a proxy through a queued old death notification. New Android boundary tests exercise expired start rejection before service IPC, a released guard's rejection and four concurrent retirement contenders yielding exactly one winner. These source additions remain unrun pending the unified build/CI.

Candidate stop/finish race repair (Android acceptance pending): Android sends stopJob oneway and also accepts a real jobFinished callback while its execution is STOPPING. A different job's synchronous bind can delay that stop in the physical proxy's shared dispatch queue until the original Mylite session has closed. Previously this legitimate ordering threw at the missing session and killed the proxy, disrupting the other job. After authenticating the physical dispatcher, envelope MAC/ID and callback descriptor, the four supported nonstart messages now return explicit `delivered=false, rejection=NO_ACTIVE_EXECUTION` for absent or observed-closed sessions. Unknown operations, invalid envelopes/callbacks, a live execution's capability mismatch, start failures and real dispatch/death/timeout failures still fail. The proxy logs this one non-delivery without killing other jobs or inventing any OS ACK/finish. No retired Binder cache or capability reuse inference was added. A close after the last send check still addresses the exact original scoped callback; Android decides whether that execution is current.

`NO_ACTIVE_EXECUTION` alone does not prove the OS has already completed that run. An unknown still-active OS execution can retain its own timeout/ANR behavior; this is explicit non-delivery, not successful stop acknowledgement. The new actual Android test arranges running A, another process B blocked in real onBind for at most four seconds, actual OS cancellation of A, A's real jobFinished callback, then barrier release. Before finishing A it requires a genuine debug receipt written only after OsJobService has validated a system-UID stop transaction and successfully queued it. An explicit private request (at most 256 bytes) selects the physical ID/proxy PID/unique token; the receipt is atomic, contains only those identities and elapsed time, and never authorizes delivery. The test checks its token/ID/PID/time under B-bound+3000ms, rather than assuming cancel's return proves stop reception. This observation is disabled in nondebuggable hosts; receipt errors do not alter real dispatch, and no token is logged. It checks B's real start/finish, OS record removal, unchanged proxy PID and no A onStop invocation. The barrier is released and the opt-in request cleared in finally, original failures remain, and neither the production eight-second budget nor existing recovery waits are extended. Boundary tests cover all four nonstart messages, unsupported/start/callback rejection, live capability mismatch and an exact Session retained across close. These candidates have not yet been run on Android and do not establish the cause of the earlier first-execution report failure.

Cold reboot exposed a pre-signal native startup race in bundled CI40113643844. Candidate readiness now refreshes a changing startup cohort only before any signal/action/mask mutation and under the original 250ms deadline. Cohort validation after preparation and acknowledgement remains strict. Failed, validated guest reservations are retired and held until actual Binder death even without an alarm deadline. Session cleanup tolerates a death link that was never established, still releases the physical guard asynchronously, and remains idempotent; an Android regression checks that exact early-failure path. This does not convert a failed job into a completed job or submit replacements outside Android's retry policy. The failed CI is retained. Repairs passed both a727f16 cloud workflows and both subsequent 02e955a workflows, each including an actual original-job reboot test; OEM recovery is still pending.

Reboot-persisted jobs now use Android's actual durable JobInfo. The host requests RECEIVE_BOOT_COMPLETED; the virtual creator must also request it in its real committed manifest. The existing stable HMAC key authenticates the exact original job/creator; only an authenticated persisted job can cross a boot boundary, and the SDK/schema, current appId/signers and enabled JobService remain checked. Nonpersistent jobs retain boot rejection, including a simulated next-boot negative. Android remains the only pending-job database. Unknown SDK upgrades, transient Binder/FD data and URI/content-trigger cases are not silently accepted.

The original copies JobInfo, saves virtual job/user/component fields in extras, substitutes a physical ProxyJobService and maps job IDs. Its service connection obtains the actual guest IJobService and forwards start/stop. Callback methods translate the physical job ID, including dequeue/completeWork. Its failure helpers can report completion without a real guest result; Mylite must preserve visible failure instead of treating those helpers as acceptance. Original hash-derived job IDs can collide, so allocation must check actual OS jobs.

Implementation boundary: registered guest PID/package/generation -> server -> actual OS scheduler -> permission-protected physical service -> current guest JobService -> authenticated real callback. OS constraints, work IDs and rescheduling remain authoritative. Use the platform Binder transaction constants, since Android 14 inserts callback methods and changes scheduler namespace signatures. No shadow framework AIDL definitions or fake task acknowledgements.

Nonpersistent jobs can carry a bounded signed original JobInfo in physical extras, leaving Android as the source of pending-job truth. A dedicated job-proxy process can expose genuine Binder death to Android if the guest executor or server dies. This avoids silently leaving a live physical service after its executor has vanished. Ordinary host/engine processes must not be killed as a workaround.

Unsupported shapes reject explicitly: URI grants/content triggers, nonempty transient extras, privileged scheduling/notifications and unknown protocol versions. Authenticated persisted jobs and public expedited jobs are now supported as described above; these remaining limits are not claims of original parity.

Required verification: real constrained scheduling, owner/namespace isolation, two actual OS work items and completion results, stop/reschedule/cancellation, cold engine startup, executor/server deaths and forged callers. Then repeat actual private Play startup and continue login/download/install. Fixture success does not satisfy this business goal.

The first implementation uses actual OS records, authenticated bounded envelopes signed with a domain-separated HMAC under the existing OS capability key, collision-checked physical IDs, and current installed creator certificates/appId. It validates the enabled BIND_JOB_SERVICE declaration at submission and execution. Android retains constraints and work IDs; callback forwarding checks the actual executing reservation and restores the original virtual ID/extras/namespace. Unsupported privileged callbacks remain explicit errors. The physical proxy uses its own `:engine_jobs` process, protected by BIND_JOB_SERVICE and system-UID checks. Its owner/server death guards retire only that proxy, allowing Android to observe genuine IJobService death and retry. Callback cleanup unbinds asynchronously to avoid deadlocking a synchronous guest main-thread callback.

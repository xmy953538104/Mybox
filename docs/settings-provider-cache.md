# Settings and DeviceConfig cache boundary

A real Android 14 failure in core run [40209984627](https://github.com/xmy953538104/Mybox/actions/runs/40209984627) occurred on the first Popup touch. ViewRootImpl constructed AutofillManager, which read DeviceConfig through Settings.Config. An already-cached raw provider received the guest package with Mybox's physical UID, and SettingsProvider rejected ownership. This was a main-thread Java crash, not a native signal failure. Subsequent successful rounds do not invalidate it.

New provider acquisitions already passed through the physical-provider adapter. Two cached paths bypassed that boundary: Settings.Config's independent holder, and ActivityThread.acquireExistingProvider's registered provider. Mylite now adapts only remote `settings` authority records and their provider/holder/reference-holder aliases, then the System, Secure, Global and API29+ Config caches. It uses the actual registry lock and each Settings holder's `mLock`. Binder identity, connections, reference counts, real configuration values, generation invalidation and OS exceptions remain unchanged. Empty holders still acquire normally. Other authorities retain their existing acquisition behavior.

REA inspected the supplied GBox APK SHA256 `6fcbaafbcb033b9e0cc03a5d6acaa54ca6b6cb06d16ce3c2d0657d7addfba257`: `com.vlite.sdk.client.k.N0` rewires cached provider records/holders (Evidence `ev_f9a3ba34bef38d297de14d4dfe238638e58d046fa8e79186c4ff3fc15274b4dc`); `J0` handles three Settings caches (`ev_9b8925f00f4d5eed378c27a37fd617f032126055216c3b1e6ca33ae6d96e762f`); `s0` resets the version-specific provider field (`ev_d8a519957870fe8284df06a631f32cf1b8d0c75bc43066db39c8934d2da12121`). N0/s0 contain unreliable duplicated obfuscation branches, so they establish the observed assignments, not an exact recovered control-flow graph or original runtime behavior. Original code remains private. Config and correct locking follow the retained Android framework implementation.

The Android regression prewarms all four caches, verifies idempotent same-Binder adaptation, reproduces the actual raw Config package/UID rejection, then requires real cold/hot reads, registry reacquisition and an OS configuration change becoming visible. Foreign attribution and DeadObjectException must still fail correctly. Only test setup adopts shell DeviceConfig permissions; its unique random key, extra acquisition and modified provider aliases are cleaned up. Existing real Popup input remains a separate regression.

Revision `6f87a7b`, core run [40212553355](https://github.com/xmy953538104/Mybox/actions/runs/40212553355), passed three actual Android 14 x86_64 rounds of 83 tests (89.126/59.763/59.315 seconds), including the real Config regression and Popup input. Separate account UI, permission broadcasts, clipboard/Web input, capacity, Alarm and persisted-Job reboot gates passed. Local compilation, 80 JVM tests, lint and both APK audits also passed. API26–30, Android15, OEM behavior, actual Google authentication and download/install are not established by this result.

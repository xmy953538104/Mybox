# Activity PendingIntent and notification interaction gap

After restoring actual network connectivity on Y700, Play40.0.13 reached `ForegroundCoordinatorService` and crashed while building its foreground notification: `PendingIntent.getActivity → getIntentSenderWithFeature → ServerPendingIntents.create` rejected type 2. This is a missing production capability, not an acceptable test-only failure. The next notification normalization layer also rejects content/delete/full-screen intents and actions, so merely accepting type 2 would not complete the fix.

Focused REA of the original `PendingActivityProxyStub.c` (`ev_dbb839755495db3657f4da9dcf0ff76f1b6bfac5596ed9bae3eba6ebcf38a8cb`, JADX headless 0.7.1, supplied new APK SHA-256 `6fcbaafbcb033b9e0cc03a5d6acaa54ca6b6cb06d16ce3c2d0657d7addfba257`) confirms a physical Activity trampoline. It restores the virtual Intent and user, resolves the target, and dispatches virtual startActivity, preserving a source token/result path where applicable or adding NEW_TASK for a root launch. onCreate finishes the trampoline and moves dispatch onto an executor. This observed dispatch method does not establish the creation, persistence or all flag semantics of the original implementation.

Mylite should extend the existing authenticated capability store and Activity/task routing, retaining a real OS Activity PendingIntent for notification interaction. Creation must not start guest Application or Activity. Sending must revalidate the creator installation and current target, reject tampered/stale/cross-package capabilities, and preserve immutable/mutable fill-in, one-shot, cancellation, update and request-code identity. A signed physical trampoline must survive engine-process death and forward through the existing Activity authorization path. Using a broadcast notification trampoline would change Android's notification-launch policy and is not an equivalent implementation.

Notification content/delete/action capabilities require separate translation and real user-click checks. Tests must observe actual target onCreate/onNewIntent, result/task behavior, actual OS notification dispatch, cancellation and process-death recovery. Returning an invented Binder, dropping the notification, swallowing the exception or pre-launching the target does not satisfy this requirement. Activity PendingIntent and interactive notifications remain unimplemented at this checkpoint; the candidate is not a usable Play release.

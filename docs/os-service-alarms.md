# Service alarm reconstruction

The pinned microG MCS creates its heartbeat with `PendingIntent.getService`; its reconnect uses a receiver. Mylite previously supported virtual Service sends but only broadcast/Activity capabilities at OS boundaries. Thus real MCS heartbeat scheduling failed before a durable alarm was created. Changing GCM defaults alone cannot resolve that mismatch.

Original REA `PendingServiceProxyStub.onStartCommand` (`ev_9dc5f323d02dfa192b9d7ac3bbda405f0ab3f73cc88f1e71f49a6ab1d2708eee`) queues the supplied Intent and returns NOT_STICKY. Fresh REA method `c` (`ev_2079a09a080eda9055fe6818d75f665b4dfeae468f8fe0044c6bce5b52248b6c`) decodes the envelope, checks the user field, routes through the server's actual startService and stops the proxy; decompiler obfuscation branches remain in the retained evidence. Original envelope decoding (`ev_74b506a19959919e3ea6c47010cd33305816c2eee3d9423dc28a477ec57fe260`) restores the original component/package/flags/type and extras; sender bookkeeping (`ev_319992e11aa7e8971d4cfa6c57e109c9f1d56e9cac090eb72f0bcec195648e7c`) stores the creator metadata. Alarm argument adaptation (`ev_2cdfc9fcc9a0dc1a80a225914fee5d1f1df4a56930a96b08bde3e260d1cc95ec`) attributes the real call to the host and removes WorkSource. These are static observations, not original-runtime equivalence or authority to trust unsigned caller fields.

The candidate uses an actual Android Service PendingIntent targeting a nonexported Service in the engine-server process. It reuses the existing bounded MAC store, boot, installed generation/certificate checks and interrupted-mutation reconciliation. Broadcast and Service types have different OS components, filter identities and key hashes. Only immutable explicit same-package enabled nonisolated manifest Services with no Intent flags are supported. Mutable, cross-package, unknown-component and foreground-Service OS senders remain rejected. General virtual foreground-Service sends retain their existing path.

The physical entry has two bounded workers, four queued requests and an eight-second absolute watchdog. Bootstrap, package/generation revalidation and guest-main admission share that deadline; a private ticket authenticates the newly registered process before startService. The existing component path still obtains actual Android Service admission and physical onStartCommand. PendingIntent OnFinished acknowledges OS dispatch, not guest business completion. Timeout closes future admission and stops the proxy; it does not claim to cancel synchronous Binder work already running. Multiple starts keep the proxy until all accepted work finishes or expires.

The new cloud regression must observe an actual OS record of type startService, real AlarmManager scheduling and actual guest onStartCommand output. It exercises update, cancel, removeAll, one-shot and wrong-target/mutability rejection. A second original alarm must restart a killed server and guest without any launch or reschedule, retain the same physical capability and execute in a new PID. Signed-codec tests include type/entry separation, terminal completion and rejection after package replacement. These tests have not run yet.

This does not implement arbitrary sticky/redelivery restoration, foreground-Service OS senders, repeating/listener/alarm-clock requests or all OEM/background policy behavior. GCM/checkin defaults, actual MCS connection/heartbeat and account authentication/download remain separate unfinished stages; no fake token or changed user preference is introduced.

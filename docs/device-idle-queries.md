# DeviceIdle self queries

Y700 on2c591a1 exposed a real background failure after instrumentation ended: microG's TriggerReceiver selected ordinary startService, and Android rejected the physical carrier with BackgroundServiceStartNotAllowedException. The actual device exempts physical com.google.android.gms, but does not exempt Mybox. The engine had no DeviceIdle identity adapter, so the virtual Google package could read the physical Google installation's policy. No whitelist or system setting was changed.

REA of the original embedded microG recovered startService, the battery query and foreground completion (292 verified bytes), plus Utils.isIgnoringSystem (102 bytes). The latter has an additional com.easy.abroad installed/preinstalled condition. That original environment is not reproduced by claiming our host is a system app. The full VLite DeviceIdle hook registration remains unknown; this independent boundary follows the measured mismatch and the platform contract.

The candidate maps only the bound guest's own name to the actual host for the two boolean/String DeviceIdle whitelist queries. It delegates to the original service and preserves its return value and errors. Explicit host queries retain the host name, physical foreign queries retain OS visibility checks, and foreign installed virtual targets fail explicitly instead of silently resolving an identically named physical package. Mutation calls retain their original arguments and actual OS denial.

Installation precedes the guest Application. It updates the DeviceIdle service lookup and cached managers, including the old PowerManager controller and modern DeviceIdle/PowerWhitelist/PowerExemption manager services. An unsupported signature, cache or manager layout fails binding. The real IPowerManager, WakeLock token and privileged permissions are unchanged.

The [Android8 PowerManager](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-8.0.0_r1/core/java/android/os/PowerManager.java) queries its controller directly; [Android11](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-11.0.0_r1/core/java/android/os/PowerManager.java) and [Android12](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-12.0.0_r1/core/java/android/os/PowerManager.java) use PowerWhitelistManager. [Android14 PowerManager](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/os/PowerManager.java) uses PowerExemptionManager; [its whitelist compatibility manager](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/apex/jobscheduler/framework/java/android/os/PowerWhitelistManager.java) also keeps a service and an exemption-manager reference.

Verification is pending. JVM cases model exempt physical Google versus nonexempt/exempt host, exact argument preservation, foreign virtual rejection, unknown shapes and unchanged real mutation failure. The ordinary guest reports its actual public PowerManager query from its Activity and a separately created Context; Android regressions compare both to the actual host result. These controlled boundaries do not accept non-instrumented background recovery. Correct attribution does not grant permission to start an FGS from every background state.

Google account diagnosis also remains separate. Debug builds keep only bounded primitive operation/response/empty-list counters and visibility-value counts, emitted through the existing authenticated guest diagnostic path. They never retain account names, passwords or tokens; a synchronous request response is not an authentication verdict. GoogleAccountObservationTest is an explicit diagnostic selection for an existing Store, not a default fixture or a business success test.

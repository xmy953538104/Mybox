Retained original REA links the sync callback to its74-byte WorkSource wrapper (`ev_ed66559174140b3f553a8797e0a174b7fe8b996b41475c5792f42eeed30742a0`), verified against the fixed classes4.dex. The [actual Android14 adapter implementation](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-14.0.0_r1/core/java/android/content/AbstractThreadedSyncAdapter.java) rejects start/cancel calls whose visible Binder UID is not SYSTEM_UID. Combining this platform guard with the actual wire receipt establishes the current failure; static original evidence alone did not.

## Independent candidate and affected boundaries

- An internal sync lease publishes a separate synchronous control descriptor. Ordinary guest bindings retain the real public ISyncAdapter Binder. Owner process, current installation, lease admission, component incarnation, internal consumer and the prepared server PID must agree, including revalidation for each control call. Oneway/PID0 is never promoted to a system caller.
- A narrowly scoped native view exposes UID1000 only during the authenticated dispatch into the real local Android ISyncAdapter. Raw UID/PID, kernel permissions, AppOps and system attribution remain physical. The generic application identity API still rejects root/system/PID0. Engine IPC authorization explicitly reads raw UID. Calibration is attempted before guest code only in processes declaring sync-adapter metadata; failure remains visible.
- Start and cancel run serially on a per-session control worker, outside shared bound-service callbacks and scheduler locks. Cancellation dispatch is acknowledged before lease release. Real ISyncContext.onFinished alone records success. Dispatch ACK is named separately. Active reservations remain held while a control RPC is blocked, bounding such workers to the existing two-session limit; an indefinitely hung custom adapter can still occupy those slots until process death. No production process killing is added.
- The real adapter probe checks framework initialization, remote Provider mutation, genuine completion, enabled automatic settings, actual interrupted cancellation, disabled settings and invalid account/extras. Ordinary binding plus the original WorkSource marker must not pass the platform guard. Wire receipts and fresh exported diagnostic phases are required. Native tests also exercise raw/AppOps, genuine clear/restore, thread/exception/nesting cleanup and anonymous-PID refusal. The focused cohort runs six actual tests per round, three rounds.

No original private code or binary is shipped. No account reset, cache clearing, data migration, permissions bypass or physical-device access is part of this change. The previous Y700 window ended early with debug OFF/export/HOME confirmed.

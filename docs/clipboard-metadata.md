# Focused guest clipboard metadata

The actual Google LoginActivity WebView failed at getPrimaryClipDescription because its virtual Google package did not own the host's real UID. REA of the original new GBox shows clipboard methods rewrite installed guest package arguments to the host package and delegate to the real service. Static evidence does not establish that the original enforces per-guest focus.

Mylite now adapts content/metadata reads, presence/text checks, set and clear. It validates the exact AOSP API26–35 signature, current bound package, local caller, virtual user0 and supported device/attribution. The real resumed Activity must still own its claimed ActivityThread token, current package generation and window focus. An unfocused guest receives null/false without invoking the real read and cannot replace the clipboard; it cannot borrow another process's shared-UID focus. Authorized operations call the real service from the guest process with its actual host package/user; OS AppOps, focus, device and lock checks still apply. Real results and exceptions remain unchanged.

Listener methods preserve their prior arguments/results/exceptions. Registration/removal succeeds in the fixture, but real callback attribution/focus isolation and clipboard URI grants are not yet reconstructed. The engine never records clipboard labels, values or MIME data.

Five JVM methods cover signature/identity/focus/delegation/error boundaries. A dedicated Android test seeds only its own synthetic clipboard, checks focused content/metadata and real listener registration, rejects foreign claims and unknown Activity membership, then puts a same-UID host Activity in front to prove background denial. The test clears its synthetic input and never reads the previous clipboard. CoreCI40207730922 passed three independent clipboard/Web interaction groups (10.149/8.182/7.333seconds), including actual WebView input and long-press paste. Google authentication and clipboard listener callbacks remain separate acceptance requirements.

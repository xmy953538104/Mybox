# Virtual server dependency

The build10 device failure was caused by the Android cached-process freezer. At 22:22:27 the Lenovo Android 14 system froze `Mybox:black`; at 22:23:08 a foreground microG UI process received `DeadObjectException` from virtual PackageManager RPCs; at 22:23:09 Android killed the server for a synchronous transaction while frozen. The settings provider lookup then appeared absent because the PM wrapper suppressed the transport error. No check-in credential or settings value is needed to diagnose this failure.

`BlackBoxCore` now retains one stable `ContentProviderClient` to its own non-exported `SystemCallProvider` per host/guest process while that process holds server service Binders. The platform can therefore account for the real provider dependency instead of treating the server as an unrelated cached process. The server itself resolves local services directly. Service lookups use a separate connection lock, without holding the service-cache lock across Binder calls. This requires no foreground-service notification, privileged permission, root, or UID override.

The stable connection lasts for the dependent process lifetime. Android normally terminates stable-provider dependents when the provider process dies. If loss is observed first in Java, the connection is closed, cached service handles are discarded, and further lookups fail explicitly until process restart. A surviving guest is never silently attached to a replacement server with an empty PID-to-virtual-identity registry. Cached Binder death handlers retain their existing behavior; PIN verification and caller identity rules are unchanged.

PM transport errors now throw with the original cause instead of returning null, false, empty application lists, or successful void mutation results. Successful absent-package/provider responses still return their ordinary null/false values. The microG trust decision continues to return false on transport failure, preserving its deny-on-failure behavior.

`PackageManagerFailureTest` covers transport failures and legitimate absent results. `VirtualServerDependencyTest` observes the real Android process importance for 35 seconds without virtual-server RPCs, checks that the same server stays out of the cached state behind an active instrumentation client, then performs a real PM lookup. Also verify an actual foreground guest after idle on each target firmware; instrumentation alone does not cover every OEM process policy. Server-death recovery deliberately requires a full dependent-process restart; this is not a transparent live migration mechanism.

Primary platform references: [ContentResolver stable/unstable clients](https://developer.android.com/reference/android/content/ContentResolver#acquireContentProviderClient(android.net.Uri)), [Android 14 provider dependency importance](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android14-release/services/core/java/com/android/server/am/OomAdjuster.java), and [Android 14 stable-provider death handling](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android14-release/services/core/java/com/android/server/am/ContentProviderHelper.java).

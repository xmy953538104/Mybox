# Self-directed component states

Mylite supports user-zero Activity/Service/manifest Receiver overrides DEFAULT, ENABLED and DISABLED with DONT_KILL_APP. The optional synchronous flag retains fsync before atomic publication. Operations requiring process termination, application-wide state changes and mutable Provider lifecycles remain unsupported. This batch does not add package-change broadcasts.

Y700/API34 Play40 exposed a missing Receiver transition during startup. Receiver mutations now use the existing authenticated generation and atomic batch path. Server selection already reads current receiver state; final guest-side admission now also re-reads the current installed manifest instead of using its sealed startup snapshot, rejecting replacement APK generations and disabled receivers before onReceive. Dynamic registrations are separate and remain registered when a manifest declaration is disabled. An already-running onReceive is allowed to complete.

The expanded fixture passed on Y700 in 3.685 seconds, including both initial and post-server-death phases: enable a Receiver declared disabled, observe its actual Intent delivery and ordered completion, disable it, observe ordered completion with no extra receiver invocation, restore DEFAULT, and retain existing Activity/Service and atomic/foreign/stale-generation checks. Provider changes continue to fail explicitly.

The server derives the writer's real process/package/generation and permits only self changes. Metadata declarations, every state, duplicate/foreign targets, flags and batch limits are checked before publishing one state file. The existing installation lock serializes state commits with APK updates; temporary-file fsync and atomic rename keep readers on complete old or new records. Invalid batches and stale generations leave existing state unchanged. No physical PackageManager mutation is made for a virtual target.

PackageStore overlays overrides on fresh copies of immutable archive metadata and filters disabled components unless requested explicitly. Queries, manifest resolution and launch checks read that state. The bound guest retains all sealed Activity declarations: the server authorizes new launches against current state while existing authenticated records can outlive a DONT_KILL_APP self-disable. Service selection reads current state for new starts/binds; existing disabled services can still stop/unbind and complete their real destruction. A new PackageStore/process reads the same persisted state; DEFAULT restores the manifest value.

The signed synthetic fixture begins with a disabled Activity alias and Service. It enables and actually launches the alias, disables it while alive, checks visible resolution changes and rejection boundaries, enables/binds a real Service, disables/unbinds it and observes destruction. The host kills the exact engine server and checks the persisted override in a new guest generation, then restores defaults. A mixed invalid batch and stale-generation write cannot partially change state. API33+ additionally exercises the framework batch API and synchronous flag; that branch awaits CI.

# Guest app tasks

The actual Play53 startup caught an unsupported `getAppTasks` call. Original GBox REA shows a real Android task query, filtering by virtual task records and wrapping the matching Binder interfaces: `am.d.o.g`, Evidence `ev_cb13091ace42a167110dfbebe8edb23a19060d1e44274f68270be5b8e091406c`. Its `app.c.b.g` maps the returned task's components and base Intent (`ev_878798e600c8de65166c8ae89eb49f559ca78fe51cddc366bdd0f383355f17d9`). Those recovered methods can fall back to raw physical results; Mylite does not copy that cross-guest fallback.

Mylite enumerates actual OS AppTasks and intersects them with current root-owned task records. A live, previously claimed Activity token must independently resolve to the same physical task ID, with the root envelope still matching. A package name, shared host UID or old task ID is insufficient. Returned five-method IAppTask capabilities validate every caller's live process and sealed package generation. The real ApplicationThread comes from trusted bootstrap before guest code executes, rather than from unverified Activity API arguments. No raw OS AppTask Binder is handed out.

`getTaskInfo` reads real OS state and maps logical root/top names while stripping physical envelope extras, children, launch cookies and the delegating window token. Reads can occur during Activity lifecycle transitions without waiting for the caller's own main thread. Move, remove and exclude calls invoke the real OS, with its exceptions preserved. Explicit ordinary starts in an idle owned task reuse the existing Activity preparation and start-result path and return the actual Android integer. Removed-task source tokens cannot start another Activity while destruction callbacks are still pending.

The new Android tests exercise the five actual methods, same-app cross-process use, foreign same-UID and host denial, invalid thread/package/capability/options, real process death, and getter access from onCreate while mutations reject an unfinished transition. Core40219620916 actually passed the five-operation, caller denial, invalid start and death cases in all three rounds. Its onCreate boundary fixture failed because super.onCreate had already sent CREATED; the corrected fixture probes before that acknowledgement and also asserts an actual successful OS mutation afterwards. This correction still needs new Android execution; the full suite remains failed. Busy/reuse starts, implicit targets, non-null attribution tags, cross-package shared tasks and cold-server recent-task restoration remain unimplemented. Unknown old physical tasks are never assigned by guessing or deleted to manufacture an empty result. The older ordinary Activity queue's `queued` return semantics are a separate unfinished admission-order issue; this change does not claim to resolve it.

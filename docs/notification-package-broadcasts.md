# 下载通知的包内隐式广播

`386e3b4` 两组完整云端的六轮133项均通过，但 Y700 的真实翻译安装仍在下载服务提升为前台时失败。此前私有Parcelable与生物识别异常没有重现；这次实际错误精确匹配 ServerPendingIntents 的“Notification broadcasts require an immutable explicit manifest capability”。实时自有UID监测在完整堆栈出现后停止Mybox，未重复尝试、清账号或缓存。新会话1742185738仍OPEN/0文件，不能按界面显示“打开”记为安装。

首项诊断复核原版通知/私有载荷/类型链，再补原版 PendingReceiverProxyStub.c（438字节，REA `ev_e6a4821485f5aba88cafd42a351bafec438d7e6e5332f79576c783fae11bf260`）及原签名Play40实际配置：DownloadService.onStartCommand（164字节，`ev_682ed5798ac23ff6c8d29c0e57735b9c381c0eda8c8b9ca12a1b91aaddf165ee`）接收已经构建的通知后调用真实startForeground；oum.a（1548字节，`ev_d2e8315d0bda5d4d78993118d41ace746c1515e4af200ae0cf869df17ac6d296`）以0x0c000000（UPDATE_CURRENT|IMMUTABLE）创建包名com.android.vending、无Component的广播，action包括NOTIFICATION_CANCEL/UNINSTALL/USE_DATA/DISMISSED。真实清单中唯一匹配接收器为非导出DownloadNotificationActionReceiver，运行在:background。原版utils.f.d保留原始Intent过滤身份并包装到物理代理，不要求原Intent一定有Component；不可只对照Service.startForeground一个方法。

本候选扩展现有不可变OS广播能力：原始Intent必须限定创建者自己的包、包含action，且当前清单只有一个可用匹配接收器。使用已有ManifestIntents解析器，保留MIME、类别、enabled/direct-boot等匹配及真实签名/包代次/boot/HMAC/撤销/权限边界；不修改逻辑Intent或PendingIntent过滤身份。服务端在投递时解析实际组件，启动客体后再次核目标，实际Receiver在客体ClassLoader执行并完成goAsync。原有journal编码已支持null Component，无格式迁移。Service仍需显式目标；mutable、跨包、registered-only、空action及多个/零清单目标不能借此取得OS投递能力。

FGS用例改为原版同样形态的包内隐式广播及客体私有嵌套载荷，并真实发送Android通知中的动作能力，要求实际Receiver/goAsync回执和原始逻辑Component仍为空；原显式通知的SystemUI点击/滑除/冷恢复负例继续保留。补唯一/歧义匹配、跨包/空action/可变性拒绝、Service边界和保存/解码回归。尚待完整两组验证，不能称已完成真机下载、安装、打开，也没有据此宣称任意隐式多目标或registered receiver的完整兼容。

本轮还保留非fatal SearchRecentSuggestions.notifyChange同步标志拒绝、重复LogAuthSpec提供者以及四次SQLiteReadOnlyDatabaseException；其与下载阻断的因果关系未确立，本候选不吞掉这些错误，也不把它们记作解决。真实代理CDN路径、最近任务历史卡片及完整性能对照仍未完成。

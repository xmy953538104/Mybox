# 客体网络配置与本轮实机失败

完整实机记录已关联：Tasks进入主界面；Apple Music由用户真实安装了ARM64 base+2split，但创建Application时在NetworkSecurityConfigProvider.handleNewApplication失败；翻译PID22490的BlobStore.getLeasedBlobs抛SecurityException；商店搜索进入重试页，同进程记录getItems HTTP400，具体请求因果尚未确立。关闭调试及导出后的日志确认PID与客体归属，没有继续占用Y700。

本次先复用原样本REA的10方法7120字节整链核验，再重核q0（ev_a18c16da31aaefd9464d6d2828e51131ee42639b7c0857f5c841e2b8f3a91f5f；classes4 SHA256 ac17de00d90982e036853c804fd9ae304cd28309f4ea1f3862df887060d16d09）。原P0在SDK30及以上按客体/宿主配置资源分支，T0在Application创建前调用P0/S0；r0在选定Google服务创建/重建前清除或重新建立配置。原q0清单例并调用install，可能捕获重复安装Provider的异常；不能把“单例非空”当作策略完整安装的证据。原始工件及反编译代码继续保存在仓库外。

[AOSP14初始化实现](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/security/net/config/NetworkSecurityConfigProvider.java)在旧/新明文策略不同且存在域名配置时会抛异常；install在设置ApplicationConfig后尝试插入AndroidNSSP，重复插入可在libcore策略更新前失败。[ManifestConfigSource](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/security/net/config/ManifestConfigSource.java)使用客体ApplicationInfo及其真实资源，不能删掉配置资源来绕过冲突。[RootTrustManagerFactorySpi](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-14.0.0_r1/core/java/android/security/net/config/RootTrustManagerFactorySpi.java)的默认信任管理器捕获当前ApplicationConfig；只换单例不足以更新已缓存TLS默认值。

Mylite此前直接调用makeApplication，缺少上述客体策略准备。候选在唯一客体执行进程内、makeApplication前建立真实ManifestConfigSource，先验证XML，再设置ApplicationConfig及libcore策略，使用系统AndroidNSSP创建TLS默认值，并同步HttpsURLConnection默认工厂。保留已有Provider，失败显式终止绑定并写固定结构诊断；没有关闭证书或pin验证，没有按Apple/Google包名特判。此过程不会改变其他宿主/客体进程的配置；已经被先前宿主代码保存的独立网络客户端实例不会被追溯重建。

新增独立普通APK的allowed/restricted两种XML策略，要求真实Application和Activity启动、不同客体PID、宿主策略不变、域名明文规则、可信自有CA通过、错误pin及非信任证书被拒绝、两种默认工厂完成本地TLS握手；每轮导出原始结果。检查覆盖主调用点、隐藏API访问、fixture构建/测试资源及云端证据采集。尚未完成云端运行，Apple具体OEM异常消息及其XML未取得，因此只是已证实缺口的候选修复，不宣称已解决Apple实机启动。BlobStore、Tasks同步、商店400及真实下载闭环继续分别查证。

# Guest application locales

Historical Bcore prototype documentation. The active Mylite implementation and its verified limits are documented in [mylite-locales.md](mylite-locales.md); the behavior below must not be attributed to Mylite.

On Android 13+, the real LocaleManager sees the host UID, which does not own a virtual package such as `com.android.vending`. Forwarding that package's `setApplicationLocales` call therefore requires the privileged `CHANGE_CONFIGURATION` permission and crashes an ordinary host.

Mybox instead stores each guest's requested locale list under its own virtual user_de data directory. An atomic file and an inter-process file lock protect the preference. Uninstalling the guest removes the preference with its data. Calls must name the currently bound guest and the current physical Android user; changing that argument cannot select another virtual user. Other package/user reads and writes are rejected.

Application and activity resources receive the requested languages followed by the actual system languages. The initial resource update runs in `AppInstrumentation.newApplication`, before application attachment and provider creation. Application callbacks, active activities, and other processes of the same guest receive subsequent preference changes; activity declarations determine configuration callback versus recreation. A directory observer watches committed file changes. The system locale getter remains a read-only platform query. No setter reaches the real system service, no system Resources object is updated, and no privileged permission is granted.

The independent `LocaleCompatibilityTest` launches the probe APK, checks an actual French resource and configuration callback, checks a provider in another process, rejects foreign package/user access, stops the guest and checks persistence before provider `onCreate`, then clears the override. It compares the real host and system locale preferences before and after. Compiling these tests does not establish that their device assertions pass.

Limits: dynamic supported-language overrides (`setOverrideLocaleConfig`, added in Android 14) explicitly throw `UnsupportedOperationException`; the corresponding getter returns null because no override exists. Raw LocaleManager Binder transactions are rejected. Android Settings integration, installer/backup language notifications, and framework-wide behavior for arbitrary custom configuration contexts are not implemented. Arbitrary custom configuration contexts are not tracked; the resource updates target the guest Application and its activities, with activity resources reapplied during creation/start/resume. This is a compatibility layer for applications sharing a host UID, not a security boundary against hostile guest code.

# Physical package events and guest Application lifetime

The exact Play53 sample logged Application initialization twice in the same PID during full run [40214099474](https://github.com/xmy953538104/Mybox/actions/runs/40214099474). Between those logs, the OS reported removal of the separately installed physical Play package. The first guest onCreate was still running, so framework messages could execute before the later Activity launch. This is a concrete correlation, not yet a recorded cache-object transition or proof of the sole startup cause.

Original GBox explicitly handles this boundary. REA of `com.vlite.sdk.client.hook.service.am.a.q`, Evidence `ev_5c8cc3f4a6bc3f68c5460216cdeacb3420e2aaea668df158dd84b8e9ca24d890`, filters its initialized guest name from a physical PACKAGE_REMOVED message, consumes an entirely filtered list and otherwise lets Android handle the remaining names. Official Android26/34 constants identify removal as command0; ActivityThread removes both LoadedApk caches on that command. A missing cached Application then permits a later Activity to construct another instance. [AOSP Android14 handler](https://android.googlesource.com/platform/frameworks/base/+/android-14.0.0_r1/core/java/android/app/ActivityThread.java)

Mylite now resolves the actual framework message/command fields and protects only the already loaded guest package. Mixed removal lists retain every other entry, their order and all other message fields; replacement, don't-kill, unrelated and unknown messages continue normally. This does not ignore a container package update or fake an Application lifecycle callback. Guest installation generations and restart requirements remain enforced by the server.

Static boundary checks cover mixed/duplicate removal, full consumption, unbound and unrelated/replacement cases. A real Android regression queues the framework ApplicationThread message, verifies both cache objects and the same Application, checks unrelated cache removal and launches another Activity through actual resume/destruction. Round17 complete compilation, 91 JVM checks, lint and both APK audits passed. New Android execution and the real Play login/download/install journey remain pending.

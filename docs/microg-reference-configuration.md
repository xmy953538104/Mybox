# Reference microG configuration behavior

GBox's preset microG contains compatibility behavior beyond the application container. The inspected preset APK SHA256 is `9025b3c5dadb589118abe6984badf2e0952384a41f1ae5d6b31851e0d44954b0`. REA recovered the complete 23,960-character Smali of `PhenotypeServiceImpl.getConfigurationSnapshot2` after Java decompilation failed (Evidence `ev_54f9189bdca0ddd4fec87496558763cb8cf47b107e57c95500009cc3a0abea6f`). This closes the earlier 664-instruction coverage gap for this method; it is static evidence, not an application acceptance result.

The method first checks its configuration map. Otherwise, twelve explicit namespace cases cover eight Photos namespaces, three Tachyon/Meet namespaces and Classroom. Photos reads bundled JSON; Tachyon reads XML configuration and adds a small set of flags; Classroom selects flags according to the supplied user/token inputs. Other namespaces receive the method's default configuration result. The separate map initializer is also fully recovered as Smali (Evidence `ev_b02098f7447a737df685df455a85d23b9933a209a2f688e95255d4c32baf35c0`): its four entries cover Google Search, Gboard and two Gmail namespaces. Neither this initializer nor this method contains a dedicated Play namespace. That bounded observation does not exclude other compatibility paths elsewhere in microG or GBox.

Our pinned open-source microG revision `32bc8954ff872d0e1a05ddfae81561b6dbecef69` already has its own twelve-entry configuration map, including Photos and Meet. Its corresponding `getConfigurationSnapshotWithToken` serves that map or the default result; it does not reproduce the original method's asset-backed Photos/Meet branches. Namespace overlap alone is not equivalent behavior. Original private source, opaque configuration assets and their flag payloads are not copied into the public repository. Reconstructing required behavior needs source provenance plus actual app/version tests.

Separately, the exact failing Play 35.6.11 APK shows a GServices prefix-cache distinction: `aivx.k` maps a null cursor through `aivv(0).a` to null, so `aivx.l` returns without marking prefixes loaded. Later matching uncached reads can repeat the prefix query. Evidence: `ev_dfb23a70e8a1b8f10f57ada95582e5830f866292191c4abe54de62c4d2217c50`, `ev_79a83934bc36bce26e467f5d76faeca4e303bd2e5872f722d6d6be810d2de37c`, `ev_3b1205ea260a9920dc4b152a8a7079f034017c00e1e47345caf32388f980cef3`, `ev_5fff417097aa24d21ad9c5edefe4da5e75e4840cbac87941f8995d39b1eb0bc0`. The failure snapshot enters this path, but it does not count all null-prefix results or prove they alone caused the timeout. Original microG also returns null for an empty query; its hot path lacks the current upstream caller/signature checks. Mylite retains those checks. Removing authorization is not a performance fix.

Next acceptance remains actual Google login and Play download/install, followed by application-specific Photos, Meet, Gmail, Gboard and Classroom behavior. The original bundled Play 40.0.13, failing image Play 35.6.11 and newer image Play 53.6 are separate versions; analysis of one cannot stand in for another. No full configuration or performance parity is claimed.

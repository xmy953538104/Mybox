# Actual physical network attribution

Play reached microG LoginActivity but WebView aborted when ConnectivityManager sent com.google.android.gms to Android under the physical host UID. The adapter leaves virtual package identity intact and changes only the known physical IConnectivityManager attribution arguments to the actual host package/tag. Request UID must be this guest, its physical owner or the platform's -1 default; foreign UID/package and virtual-user queries are rejected. No network state, permissions, availability event or callback result is fabricated. Android still applies the real UID's permissions and quotas.

API31/34 signatures were checked against the corresponding AOSP IConnectivityManager AIDL. Local queries, default-network callback and listenForNetwork callback were exercised from a real guest, matching the host's actual active Network handle. A forged package was rejected. Original-artifact REA listenForNetwork evidence `ev_8d127a21c61c940f06b90154b997d4b30a27d3e22ed2d8347ba22cf1b3d9c0c9` shows a dedicated network service and a virtual NetworkRequest; helper m0 evidence `ev_15242289603e5d53bef58e2ae912f035af591f6c95fea17e38674e62b5a2624b` requests host listening using the context package and attribution tag. This establishes a service boundary, not identical original callback multiplexing. Proprietary source and APKs remain private inputs.

Actual local Play now opens Google's credential form through microG and returns to Play on Back, with no real account entered. That is login-entry progress only. Account completion, catalogue and downloading/installing remain unaccepted. PendingIntent network delivery and unknown OEM/version signatures deliberately fail instead of pretending to work; they require their own delivery and ownership evidence when encountered.

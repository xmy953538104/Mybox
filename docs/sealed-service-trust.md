# Avoid repeated full-APK hashing on identity RPCs

The real Play35 startup failure in run `40181791456` now has a complete observed chain: Play main waits for its initialization Future; its worker queries `com.google.android.gsf.gservices`; microG's GServicesProvider waits for MyboxIdentity.resolve; the engine_server identity Binder thread is in `NativeCrypto.EVP_DigestUpdate → TrustedMicrog.verify → require → IdentityProvider.call`. This establishes repeated full-APK verification as work on the blocked identity path, rather than a demonstrated Service-bind deadlock. Removing that repetition must still be validated against actual Play startup.

`TrustedMicrog` now caches one fully verified sealed APK per process. Each call still validates the package and exact signer pin, opens the actual file and checks its device/inode, owner/group, link count, size, read-only mode, and nanosecond modification/change timestamps. The cache key also contains the committed generation path and both host asset pins. A writable or non-regular file is refused. The open descriptor and current path must match before verification and still match after the complete digest.

Newly changed files are not promoted into the cache for two seconds: this avoids treating multiple changes within a coarse filesystem timestamp tick as unchanged. A significant wall-clock/monotonic-clock offset change invalidates a cache hit. Changed metadata or pins requires full verification; changed bytes still fail the original SHA-256 check. The cache is process-local and cannot survive a host restart. The container continues to share a physical UID and is not a hostile-code security boundary.

API26 keeps full verification because nanosecond stat timestamps are unavailable there. API27+ uses the platform's [StructStat timestamps](https://developer.android.com/reference/android/system/StructStat), obtained from the actual descriptor with Os.fstat rather than only File.lastModified.

Y700/API34 tests passed (two tests, 6.493 seconds): an unchanged sealed file hits the cache; another signer or host digest pin cannot reuse approval; writable files and same-length tampering with restored modification time are rejected; atomic inode replacement forces full verification; simultaneous cold readers perform exactly one full digest. The real pinned microG and real Play paths require their separate runtime results; these synthetic negative tests do not replace them.
